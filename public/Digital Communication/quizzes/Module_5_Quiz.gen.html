Part A — why each option is right or wrong

A1. Correct answer: (A) M + 1

  • (A) Correct - it counts the input bits influencing any one output bit.
  • (B) Wrong - M is the memory order; the current input must be counted as well.
  • (C) Wrong - that is the number of trellis states.
  • (D) Wrong - this is smaller than the memory, which cannot be right.

A2. Correct answer: (A) 8

  • (A) Correct - 2^M = 2^3 = 8.
  • (B) Wrong - that is the memory order, not the state count.
  • (C) Wrong - that would be M = 2.
  • (D) Wrong - that would be M = 4.

A3. Correct answer: (A) 111 and 101

  • (A) Correct - 7 is 111 and 5 is 101 in three-bit binary.
  • (B) Wrong - 110 is 6 and 100 is 4.
  • (C) Wrong - 011 is 3, not 5.
  • (D) Wrong - the order is reversed; the first generator is 7.

A4. Correct answer: (A) the impulse responses of its output branches

  • (A) Correct - which is why the encoding operation is a convolution.
  • (B) Wrong - parity check polynomials belong to cyclic block codes.
  • (C) Wrong - the encoder is deterministic, with no probabilities involved.
  • (D) Wrong - tail bits flush the register and are not generators.

A5. Correct answer: (A) To return the encoder to the all-zero state so the decoder has a known endpoint

  • (A) Correct - and they cost rate, which matters for short messages.
  • (B) Wrong - they lower the effective rate rather than raising it.
  • (C) Wrong - frame marking is a separate function performed elsewhere.
  • (D) Wrong - randomisation is the job of a scrambler.

A6. Correct answer: (A) 2^L

  • (A) Correct - which is precisely why the tree is useless for real decoding.
  • (B) Wrong - that is the number of distinct states, not paths.
  • (C) Wrong - that is the Viterbi work count, which is the point of merging.
  • (D) Wrong - the growth is exponential, not polynomial.

A7. Correct answer: (A) nodes with the same state at the same time are merged

  • (A) Correct - merging keeps the width constant at 2^M.
  • (B) Wrong - the trellis shows every possible path, just compactly.
  • (C) Wrong - branch output labels are retained and essential.
  • (D) Wrong - the trellis does not grow at all in width.

A8. Correct answer: (A) 2^M, constant in sequence length

  • (A) Correct - and that constancy is what makes Viterbi decoding linear in L.
  • (B) Wrong - that is the tree path count.
  • (C) Wrong - the width is fixed after the first M steps.
  • (D) Wrong - the rate is a ratio, not a node count.

A9. Correct answer: (A) removed, because it represents staying in the zero state

  • (A) Correct - and the zero state is split into a source and a sink.
  • (B) Wrong - keeping it makes the series diverge without adding information.
  • (C) Wrong - labelling it does not solve the divergence problem.
  • (D) Wrong - no such substitution is part of the method.

A10. Correct answer: (A) the minimum weight of a path diverging from and remerging with the all-zero path

  • (A) Correct - it is defined relative to the all-zero path, which linearity permits.
  • (B) Wrong - there are no fixed-length codewords in a convolutional code.
  • (C) Wrong - K influences d_free but is a different quantity.
  • (D) Wrong - the state count is 2^M and unrelated to weight.

A11. Correct answer: (A) 4 dB

  • (A) Correct - and the infinite response is exactly what turbo codes exploit.
  • (B) Wrong - the free distance is identical, which is why RSC alone is no better.
  • (C) Wrong - the state count is unchanged.
  • (D) Wrong - the rate is unchanged.

A13. Correct answer: (A) maximum likelihood sequence estimation over all trellis paths

  • (A) Correct - and the Viterbi algorithm achieves it exactly, not approximately.
  • (B) Wrong - the memory couples the bits, so independent decisions are suboptimal.
  • (C) Wrong - syndromes belong to block codes.

  • (A) Correct - discarded paths provably cannot win, so nothing optimal is lost.
  • (B) Wrong - it returns precisely the maximum likelihood sequence.
  • (C) Wrong - it is optimal for soft decisions too; only the metric changes.
  • (D) Wrong - it applies to any rate and any constraint length.

  • (A) Correct - add the branch metric, compare the candidates, select the survivor.
  • (B) Wrong - metrics are added, not multiplied, because logarithms are used.
  • (C) Wrong - there is no sorting; each state has only two candidates.
  • (D) Wrong - the recursion is sequential in time, not a divide-and-conquer split.

  • (C) Wrong - leaving the zero state is entirely normal.
  • (D) Wrong - truncation depth governs traceback, not the discard decision.

A18. Correct answer: (A) 5 times the constraint length

  • (B) Wrong - deleting bits raises the rate rather than lowering it.
  • (C) Wrong - the encoder and its memory are untouched.
  • (D) Wrong - the same Viterbi decoder is used with neutral metrics at punctured positions.

B1 (3 marks) — CO5, L4, Ch.10, pp.605-608

Question. Draw and explain the rate 1/2, K = 3 convolutional encoder with generators (7,5), and encode the message 1011 with tail bits.

Model answer. The encoder has two memory stages. The first adder taps the input and both stages, corresponding to 111 or octal 7; the second taps the input and the second stage, corresponding to 101 or octal 5. Starting from state 00 and feeding 1,0,1,1 then two zero tail bits: input 1 from 00 gives outputs 11 and moves to 10; input 0 from 10 gives 10 and moves to 01; input 1 from 01 gives 00 and moves to 10; input 1 from 10 gives 01 and moves to 11; tail 0 from 11 gives 01 and moves to 01; tail 0 from 01 gives 11 and returns to 00. The transmitted sequence is 11 10 00 01 01 11, twelve bits for four information bits.

B2 (3 marks) — CO5, L4, Ch.10, pp.608-613

Question. Explain why the trellis replaced the code tree, and quantify the saving.

Model answer. The code tree doubles in width at every time step, giving 2^L paths after L steps, which is intractable beyond about ten steps. But beyond depth M the tree is redundant: nodes at the same depth holding the same register contents have identical futures, because the encoder output depends only on the input and the state. Merging those nodes gives the trellis, which has exactly 2^M nodes at every step regardless of L. For a K = 3 code and a 100-bit message, the tree has 2^100 or about 1.3 x 10^30 paths, while the trellis has 4 states at each of 102 steps, roughly 400 node updates. The information content is identical; only the redundancy is removed.

B3 (3 marks) — CO4, L5, Ch.10, pp.608-613

Question. Define free distance, explain how it is obtained from the transfer function, and compute the coding gain for the (7,5) code.

Model answer. Free distance is the minimum Hamming weight of any path that diverges from the all-zero path and later remerges with it; by linearity this is equivalent to the minimum distance between any two distinct paths. To obtain it, label each edge of the state diagram with D raised to the weight of its output, split the all-zero state into a source and a sink, remove its self-loop, and solve the flow graph. For the (7,5) code this gives T(D) = D^5/(1 - 2D) = D^5 + 2D^6 + 4D^7 + ..., so the lowest exponent is 5 and d_free = 5. The asymptotic hard-decision coding gain is 10 log10(R d_free) = 10 log10(0.5 x 5) = 3.98 dB, rising to roughly 7 dB with soft decisions.

B4 (3 marks) — CO5, L5, Ch.10, pp.614-618

Question. Describe the Viterbi algorithm and explain why discarding paths loses no optimality.

Model answer. The algorithm walks the trellis one time step at a time, holding for each of the 2^M states the best path reaching it and that path accumulated metric. At each step and state it adds each incoming branch metric to its predecessor path metric, compares the resulting candidates, and selects the smaller as the new metric, recording which branch survived. Discarding the loser is safe because any future continuation from that state is available equally to both candidates: if the loser were extended to an optimal sequence, replacing its prefix with the winner would give a strictly better sequence ending at the same state, a contradiction. The algorithm therefore returns exactly the maximum likelihood sequence in O(L 2^M) work rather than O(2^L).

B5 (2 marks) — CO5, L4, Ch.10, pp.618-623

Question. The (7,5) code transmits 11 10 00 01 01 11 but 11 10 01 01 01 11 is received. Decode it and state the metric of the winning path.

Model answer. Compare the received sequence against the correct path branch by branch. The first two pairs, 11 and 10, match exactly, contributing 0 to the metric. The third received pair is 01 while the correct branch label is 00, a Hamming distance of 1. The remaining three pairs, 01, 01 and 11, all match, contributing 0. The correct path therefore accumulates a metric of 1. Every competing path through the trellis picks up a metric of 3 or more, because any divergence from the correct path must have weight at least d_free = 5 relative to it and can gain at most the one erroneous bit. Tracing back from the terminal all-zero state recovers the message 1011.

B6 (2 marks) — CO5, L5, Ch.10, pp.618-623

Question. Explain what truncation depth is and what happens if it is set too small.

Model answer. Storing survivor decisions for an entire continuous stream is impossible, so a practical decoder traces back a fixed number of steps T, outputs the information bit at the oldest position, and slides the window forward one step. This works because survivor paths from different states converge as they are traced back, so beyond a certain depth all survivors agree on the old bits. A truncation depth of about five times the constraint length makes non-merged tracebacks negligibly rare. If T is set too small, typically equal to K, the paths have often not merged, so the bit output depends on which survivor the traceback started from, and the decoder introduces errors that it would otherwise have corrected.

B7 (2 marks) — CO5, L4, Ch.10, pp.618-623

Question. Compare hard and soft decision decoding, stating the gain and the cost.

Model answer. Hard decision decoding slices the demodulator output to one bit and computes branch metrics as Hamming distances, so a marginal decision and a confident one carry equal weight. Soft decision decoding keeps a multi-bit demodulator output and computes Euclidean distances or correlations, so the decoder knows how reliable each received bit was and can let confident bits outvote doubtful ones. The gain on an AWGN channel is about 2 dB. The cost is small: a three-bit bus from the demodulator instead of one bit, and wider adders in the metric computation, since three bits of quantisation captures nearly all the available gain and eight bits adds under 0.1 dB more. The trellis, the survivors and the add-compare-select recursion are completely unchanged.

B8 (2 marks) — CO4, L5, Ch.10, pp.610-613

Question. What is a recursive systematic convolutional code, and why is it used in turbo codes?

Model answer. An RSC encoder passes the information bit through unchanged as one output and feeds one generator output back into the register input, making the code systematic and giving it an infinite impulse response. Any non-recursive code has an RSC equivalent with identical free distance and identical trellis, so as a standalone code it performs the same. Its value appears in concatenation: because a single input 1 produces a parity sequence of infinite weight, a low-weight input sequence cannot easily produce a low-weight codeword. Two RSC encoders separated by an interleaver therefore rarely produce a low-weight output for the same input, which is what gives turbo codes their steep waterfall near capacity.

B9 (2 marks) — CO5, L5, Ch.10, pp.618-623

Question. Explain puncturing and compute the puncture pattern needed to reach rate 3/4 from a rate 1/2 code.

Model answer. Puncturing deletes selected coded bits according to a fixed periodic pattern before transmission, raising the rate without changing the encoder or decoder structure; the decoder simply inserts a neutral zero metric contribution at each deleted position. To reach rate 3/4 from a rate 1/2 base, take 3 information bits, which the base encoder turns into 6 coded bits, and transmit only 4 of them, deleting 2 per period of 6. The resulting rate is 3/4. The pattern must be chosen from published tables, because the choice of which bits to delete determines the free distance of the punctured code; an arbitrary pattern can cost several decibels for the same rate.

B10 (2 marks) — CO5, L4, Ch.10, pp.605-608

Question. Explain why tail bits reduce the effective rate and compute the loss for a 20-bit message with K = 7.

Model answer. The encoder must be returned to a known state so the decoder has a fixed endpoint for its traceback, which requires feeding M zero bits after the message. Those bits carry no information but are encoded and transmitted like any other, so the transmitted length grows from nL to n(L + M). For K = 7, M = 6, and a 20-bit message at rate 1/2, the transmitted length is 2 x 26 = 52 bits rather than 40. The effective rate is 20/52 = 0.385 rather than 0.5, a loss of 23%. For a 1000-bit message the same 6 tail bits cost only 0.6%, which is why short-frame systems use tail-biting termination instead.

B11 (2 marks) — CO4, L5, Ch.10, pp.605-623

Question. Compare block codes and convolutional codes, and explain why the classic satellite system uses both.

Model answer. Block codes need frame alignment and bound the effect of a burst within one block, and Reed-Solomon codes in particular correct symbol errors directly, which suits bursty channels. Convolutional codes need no alignment, suit continuous streams, and exploit soft demodulator outputs naturally for about 2 dB, but when the Viterbi decoder does fail it produces a multi-bit error event spanning several trellis steps rather than a single bad bit. That failure mode is precisely what a Reed-Solomon outer code handles well, since a burst of adjacent bit errors usually falls within a small number of RS symbols. The classic concatenated system therefore places a convolutional inner code next to the channel, an interleaver to spread residual bursts, and an RS outer code to clean up what remains, for a total gain of around 7 to 8 dB.

B12 (2 marks) — CO5, L4, Ch.10, pp.605-608

Question. Show that the impulse response of the branch with generator 111 is 1,1,1 and explain the term convolutional.

Model answer. Feed the sequence 1,0,0,0,... into the encoder starting from the all-zero state. At time 0 the input is 1 and both stages are 0, so the adder tapping input and both stages outputs 1. At time 1 the input is 0, the first stage holds 1 and the second 0, so the output is 1. At time 2 the input is 0, the first stage 0 and the second 1, so the output is again 1. At time 3 the register is clear and the output is 0 thereafter. The impulse response is therefore 1,1,1, exactly the generator. Because the output of a linear time-invariant system is the convolution of the input with the impulse response, the encoder output is the convolution of the message with the generator sequences, which is where the name comes from.

Question. A designer proposes K = 12 to get more coding gain. Explain why this is a poor choice.

Model answer. Free distance and therefore coding gain grow only slowly with constraint length, roughly logarithmically in practice, while the Viterbi decoder state count grows as 2^(K-1). Going from K = 7 to K = 12 multiplies the states from 64 to 2048, a thirty-two-fold increase in add-compare-select operations, survivor memory and power, in exchange for perhaps 1 to 1.5 dB of additional gain. Truncation depth also grows as 5K, increasing latency. If more gain is genuinely needed, concatenation with an outer Reed-Solomon code, or a modern turbo or LDPC code, delivers far more per unit of complexity. K = 7 sits near the knee of the cost-benefit curve, which is why it became the industry standard.
