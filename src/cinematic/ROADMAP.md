# Platform Roadmap — After Engine Freeze (V7+)

## Investment model

| Focus | Share | Allowed work |
|-------|------:|--------------|
| **Engine** | **20%** | Bug fixes, performance, accessibility, tooling, documentation |
| **Content** | **80%** | Diagrams, storytelling, examples, simulations, quizzes, assessments, revision experiences |

## Engine (20%) — what is still allowed

- Fix regressions that hurt classroom use
- Performance on modest hardware
- Accessibility (reduced motion, contrast, lecturer control)
- Tooling (QA, visual regression, insights)
- Documentation and SDK clarity

**Not allowed without multi-subject proof:**

- New motion systems
- New teaching modes
- Parallel APIs that duplicate frozen contracts
- Subject-specific forks of engine CSS/JS

## Content (80%) — where value lives now

- Better diagrams and subject-specific simulations
- Richer narrative and examples
- Interactive learning moments that use existing motion/film meta
- Quizzes, assessments, revision packs
- Subject identity craft (tone, metaphor, motifs, finales)

## Decision test for any proposal

1. Does it help **multiple subjects**?  
2. Can International Business demonstrate the benefit first?  
3. Is it additive to a frozen contract?  
4. Does it improve **learning**, not novelty?

If the answer to #4 is weak, don’t build it.

## Final principle

The Presentation Engine is infrastructure — stable, reusable, trusted.

Every future subject should ask:

**“How can we best teach this topic using the engine we already have?”**
